UX checklist before a release

Run it on every page a release changes, and on the home page every time. Most checks are measurable; pack/measure.mjs measures the ones marked (m). Each line links the principle behind it.

Set up

  • Write down the reader and the question they arrive with. Without one, this checklist is a matter of taste.
  • Open the page in a real browser at 390 × 844 (a phone) and 1280 × 800, in light and dark.

The first screen (on the phone)

  • [ ] It says what this is, who made it, and the next step (1).
  • [ ] The product or thing is named by its full name (2).
  • [ ] Any number with £ or € says what it is in the words beside it (7).
  • [ ] Every main section is reachable in one tap (a Menu counts) (18).
  • [ ] Shared in a chat, the link shows a card, a title and a description (Open Graph tags; a 1200 × 630 JPEG under 300 KB). For many readers the preview is the first screen.
  • [ ] The site's own name is not cut (m) (21).

Layout (m)

  • [ ] No sideways scroll at 390 px: scroll width equals viewport width (21).
  • [ ] No text under 12 px; no tap target under 24 px; navigation targets 44 px (23).
  • [ ] No floating control covering text.
  • [ ] Page height in phone screens noted, and compared with the last release (22).
  • [ ] Every image has alt text (empty for decoration).
  • [ ] No page errors in the console (27).

Words

  • [ ] No internal ids, file paths, status codes, agent addresses or team verbs in reader text (5, 6).
  • [ ] Acronyms glossed on first use.
  • [ ] Generated strings tried with 0, 1, many and unknown (10).
  • [ ] Every status label uses the source's own words (8).
  • [ ] Each link's words name where it goes; outside links show the address (17).
  • [ ] The same place has the same label as on sister sites (20).

Honesty

  • [ ] What is not here yet is said, with a date (11).
  • [ ] Every "tell us", button and promise has a working route; if not, it is removed (15).
  • [ ] Every trust badge links to what a reader can check (12).
  • [ ] Nothing on the page contradicts anything else on it, footer included (13).
  • [ ] Every time shown has its age or a date; nothing says "today" or "live" after the event (14).
  • [ ] Made-up examples, simulations and agent authorship are labelled where they are read (16).
  • [ ] Every number comes from data, with its source (29).

States

  • [ ] The empty state says why and offers one way forward (24).
  • [ ] If a fact changed, every way in to it was checked (25).

After a fix

  • [ ] The original finding is gone, and the whole first screen was re-measured on the phone (28).
